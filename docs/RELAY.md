# MCTunnel relay — установка и настройка

Relay — это сервер на вашем VPS, через который друзья заходят в ваш мир. Мод на вашем ПК сам
подключается к нему (соединение исходящее, поэтому серый IP и CGNAT не мешают), relay выдаёт
постоянный адрес, а друзья заходят по нему обычным клиентом Minecraft.

## Что нужно

- VPS на Linux с systemd: Ubuntu, Debian и похожие системы;
- процессор amd64 (x86_64) или arm64;
- публичный IPv4-адрес;
- 1 vCPU и 512 МБ памяти хватает с запасом: relay — один статический бинарник без зависимостей.

## Установка одной командой

Подключитесь к серверу по SSH и выполните:

```bash
curl -fsSL https://github.com/Donkoev/MCTunnel/releases/latest/download/install.sh | sudo bash
```

Нет `curl` — то же через `wget -qO- <тот же адрес> | sudo bash`.

<img src="images/installer.png" width="620" alt="Установщик relay">

Установщик:
1. задаёт три вопроса: имя пользователя, адрес сервера (внешний IP он узнаёт сам, можно вписать
   домен) и порты (стандартные оставляются нажатием Enter);
2. скачивает relay той же версии из [релиза](https://github.com/Donkoev/MCTunnel/releases/latest)
   и сверяет его SHA-256;
3. создаёт системного пользователя `mctunnel` (relay работает без прав root), конфиг
   `/etc/mctunnel/relay.json` с первым пользователем и его секретом, systemd-службу
   `mctunnel-relay` и включает BBR;
4. включает файрвол ufw (ставит его, если нужно): снаружи остаются открыты только порты relay и
   SSH, все остальные входящие соединения закрываются. Исходящие соединения, ping и системные
   службы работают как раньше. Если на сервере ещё что-то слушает порты (например, сайт на 80),
   установщик покажет это и предложит оставить такие порты открытыми;
5. печатает данные для мода: адрес relay, пользователя и секрет. Их вписывают в игре:
   Esc → MCTunnel → вкладка «Сервер».

Порты по умолчанию:

| Порт | Для чего |
|---|---|
| TCP 25500 | подключение хостов, то есть мода |
| TCP 443 | TLS: для сетей, где режут необычные порты. Если 443 занят веб-сервером, установщик выключает TLS |
| UDP 25500 | KCP: для Wi-Fi и мобильного интернета с потерями |
| TCP 25565–25664 | друзья заходят в миры: у каждого пользователя свой порт, первый получает 25565, и его друзьям хватает одного IP без порта |

> [!IMPORTANT]
> Если у хостера есть свой файрвол (в панели управления VPS), откройте эти порты и там. Некоторые
> облака применяют изменения файрвола только после перезагрузки виртуальной машины.

## Меню установщика

Повторный запуск той же команды открывает меню:

| Пункт | Что делает |
|---|---|
| Обновить relay | Ставит версию из последнего релиза. Сначала проверяет её на вашем конфиге, прежний бинарник сохраняет как `/usr/local/bin/mctunnel-relay.prev` и возвращает его, если новый не запустился |
| Показать данные для мода | Адрес, пользователь и секрет: например, чтобы вписать их в другую сборку игры |
| Добавить пользователя | Ещё один хост со своим секретом и своим портом. Relay перечитывает список без перезапуска: остальные туннели не прерываются |
| Удалить пользователя | Туннель этого пользователя закрывается сразу, его секрет перестаёт работать |
| Перезапустить relay, Журнал relay | Для диагностики |
| Файрвол | Закрывает всё, кроме портов relay и SSH (прежние правила ufw сохраняются в `/etc/ufw/*.rules.<время>`) |
| Удалить MCTunnel с сервера | Служба, программа, настройки с секретами, системный пользователь и открытые установщиком порты |

**Без вопросов** (в скриптах или без терминала) действие передаётся аргументом после `bash -s --`:

```bash
curl -fsSL .../install.sh | sudo bash -s -- install --user steve --address mc.example.com
curl -fsSL .../install.sh | sudo bash -s -- update
curl -fsSL .../install.sh | sudo bash -s -- list
curl -fsSL .../install.sh | sudo bash -s -- add alex          # печатает данные для мода
curl -fsSL .../install.sh | sudo bash -s -- show alex
curl -fsSL .../install.sh | sudo bash -s -- remove alex --yes
curl -fsSL .../install.sh | sudo bash -s -- firewall --keep "80/tcp"
curl -fsSL .../install.sh | sudo bash -s -- uninstall --yes
```

`--keep "80 443/tcp 8000:8010/udp"` оставляет открытыми и эти порты, `--no-firewall` у `install`
не трогает файрвол вовсе. SSH-порт установщик находит сам (по sshd, его systemd-сокету, конфигу и
открытым сессиям); если найти его не удалось, файрвол не включается, чтобы не потерять доступ к
серверу.

У `install` есть и `--ports "25500 443 25500 25565-25664"`: TCP, TLS, KCP и диапазон игроков,
`0` выключает TLS или KCP. `NO_COLOR=1` выключает цвета, `MCTUNNEL_VERSION=1.0.0` ставит
конкретную версию вместо последней.

## Установка с Windows: deploy.ps1

Если сервер не открывает GitHub, relay можно отправить с вашего ПК. Скачайте
`mctunnel-relay-<версия>.zip` из [релиза](https://github.com/Donkoev/MCTunnel/releases/latest),
распакуйте и выполните в PowerShell в этой папке:

```powershell
.\deploy.ps1 -Server <IP сервера> -User <пользователь SSH> -SetupKey
```

Скрипт копирует relay и установщик на сервер по `scp` и запускает там тот же установщик: на новом
сервере он задаёт свои три вопроса и печатает данные для мода, а установленный relay обновляет.
Пароли SSH и sudo вводите вы сами в терминале, скрипт их не сохраняет.

`-SetupKey` один раз добавляет ваш SSH-ключ на сервер (второй раз тот же ключ не добавляется), и
дальше пароль SSH не спрашивается. Ещё параметры:
- `-Config путь\к\relay.json` — поставить свой конфиг вместо того, что на сервере (прежний
  сохраняется как `/etc/mctunnel/relay.json.bak.<время>`);
- `-Identity путь\к\ключу` — войти конкретным приватным ключом (для `-SetupKey` нужен и
  `путь\к\ключу.pub`);
- `-BindAddress 192.168.x.x` — подключаться с адреса физического адаптера, в обход VPN
  (как `ssh -b`).

## Пользователи и секреты

Пользователь — это тот, кто открывает через relay свой мир. У каждого свой секрет и свой порт
для друзей. Друзьям, которые просто заходят в мир, пользователь не нужен.

Проще всего управлять ими через меню установщика. То же можно сделать командами relay: они
меняют в конфиге только список `users` и сохраняют владельца и права файла.

```bash
sudo mctunnel-relay user list   -config /etc/mctunnel/relay.json
sudo mctunnel-relay user add    -config /etc/mctunnel/relay.json alex   # печатает секрет и порт
sudo mctunnel-relay user show   -config /etc/mctunnel/relay.json alex
sudo mctunnel-relay user remove -config /etc/mctunnel/relay.json alex
sudo systemctl reload mctunnel-relay                                   # применить без перезапуска
```

Новый пользователь получает первый свободный порт диапазона, так что адреса остальных не
сдвигаются. Можно и отредактировать `users` в `/etc/mctunnel/relay.json` руками: добавить
пользователя, удалить его, поставить `"disabled": true` или сменить секрет. Проверьте файл
(`-check`, см. ниже) и выполните `sudo systemctl reload mctunnel-relay`.

Туннель отозванного пользователя закрывается сразу, остальные не замечают перезагрузки.
Остальные настройки применяются только после `systemctl restart`: если они в файле изменились,
relay пишет в журнал, какие именно ждут перезапуска. Файл с ошибкой или закреплённый `port` вне
текущего `port_range` relay не принимает и оставляет прежний список пользователей.

Секрет делает сам relay: `user add` и `init` дают 43 символа, 256 случайных бит. Придумывать
секрет самому нельзя: по перехваченной авторизации слабый секрет подбирается офлайн. Relay не
примет секрет короче 32 символов, секрет с пробельным символом в начале или в конце (клиенты
такие символы обрезают, и войти бы не удалось) и секрет с управляющими символами.

## Конфиг relay.json

Установщик создаёт `/etc/mctunnel/relay.json` сам. Все поля — в
[`relay.example.json`](../relay.example.json). Пустые поля получают значения по умолчанию,
опечатки в именах полей relay отвергает.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `listen` | `[{"transport":"tcp","address":":25500"}]` | Куда подключаются хосты. Слушателей может быть несколько: `{"transport":"tls","address":":443"}` добавляет TLS, `{"transport":"kcp","address":":25500"}` — KCP на UDP |
| `public_bind` | `""` (все интерфейсы) | IP, на котором открываются порты для игроков |
| `port_range` | `25600–25699` | Диапазон портов для игроков. Установщик ставит `25565–25664` и закрепляет 25565 за первым пользователем |
| `max_hosts` | 16 | Сколько туннелей одновременно |
| `max_players_per_host` | 32 | Игроков на один туннель |
| `max_players_per_ip` | `max(4, max_players_per_host/4)`, то есть 8 | Игроков одного туннеля с одного IP (IPv6 — с подсети /64): один клиент не займёт все места. Поднимите, если друзья сидят за одним NAT или CGNAT |
| `max_tunnels_per_user` | 1 | Лишний туннель пользователя вытесняет его самый старый |
| `handshake_timeout` | `10s` | Время на авторизацию нового соединения. Первые 6 байт должны прийти за 3 с, по KCP — за 6 с |
| `open_timeout` | `10s` | Сколько игрок ждёт соединения от хоста |
| `max_handshakes`, `max_handshakes_per_ip` | 256, 32 | Неавторизованные соединения одновременно, отдельно на каждом слушателе |
| `auth_failures` | `{"max":5,"window":"10m","ban":"15m"}` | Бан IP (для IPv6 — подсети /64) за неудачные попытки по TCP и TLS. Неудачи по KCP не банят: адрес UDP можно подделать |
| `log_level` | `info` | `debug`, `info`, `warn`, `error` |
| `users[]` | — | `name` (1–32 символа `A-Za-z0-9._-`), `secret`, необязательный `port` (закреплённый порт из диапазона), `disabled` |

**Порт туннеля.** Закреплённый `port` зарезервирован за пользователем: другим relay его не
выдаёт. Остальные получают домашний порт, вычисленный из имени. Если он совпал с закреплённым
или с домашним портом пользователя, чьё имя раньше по алфавиту, берётся следующий. Домашний порт
зависит только от списка пользователей, а не от того, кто подключился первым. Отключённые
(`disabled`) пользователи свои порты сохраняют, так что отключение одного не сдвигает адреса
других. Пользователи, которых добавляет установщик, получают закреплённые порты.

**TLS на 443.** Слушатель `{"transport": "tls", "address": ":443"}` принимает те же соединения
внутри TLS. Снаружи это похоже на обычный HTTPS: так туннель проходит через сети, где режут
необычные порты (некоторые провайдеры, офисные и публичные сети). Сертификат relay создаёт сам.
Можно указать свой через `"cert"` и `"key"` (пути к PEM), но это не обязательно: мод сертификат не
проверяет, а подлинность обе стороны доказывают через HMAC, как и по TCP.

**KCP на UDP 25500.** Слушатель `{"transport": "kcp", "address": ":25500"}` принимает те же
соединения по протоколу KCP поверх UDP. Номер совпадает с TCP-портом, но это другой протокол, так
что порты не конфликтуют. KCP досылает потерянные пакеты за десятки миллисекунд, а не за сотни,
как TCP: он нужен хостам с потерями на канале (Wi-Fi, мобильный интернет).

Проверить конфиг и посмотреть, какие порты открыть:

```bash
sudo mctunnel-relay -config /etc/mctunnel/relay.json -check
sudo mctunnel-relay -config /etc/mctunnel/relay.json -print-ports
```

## Установка вручную

Установщик — обычный bash-скрипт: [`install.sh`](../install.sh). Если положить рядом с ним
`mctunnel-relay-linux-amd64` (или `-arm64`) из релиза, он возьмёт бинарник оттуда, а не скачает:
`sudo bash install.sh`. Совсем вручную:

```bash
sudo useradd --system --user-group --no-create-home --shell /usr/sbin/nologin mctunnel
sudo install -m 0755 mctunnel-relay-linux-amd64 /usr/local/bin/mctunnel-relay
sudo install -d -m 0750 -o root -g mctunnel /etc/mctunnel
sudo mctunnel-relay init -config /etc/mctunnel/relay.json -user steve   # печатает секрет
sudo chgrp mctunnel /etc/mctunnel/relay.json && sudo chmod 0640 /etc/mctunnel/relay.json
```

systemd-юнит (без root, с фильтром системных вызовов и урезанным `/proc`) и настройки BBR
установщик пишет из функций `write_unit` и `write_sysctl`: возьмите их оттуда. Порты откройте у
хостера и в фаерволе сервера, если он включён:

```bash
sudo ufw allow 25500/tcp
sudo ufw allow 443/tcp
sudo ufw allow 25500/udp
sudo ufw allow 25565:25664/tcp
```

**BBR.** Этот алгоритм управления перегрузкой заметно лучше ведёт себя на каналах с потерями, а
у игроков с мобильным интернетом и CGNAT они обычны. Установщик кладёт в
`/etc/sysctl.d/99-mctunnel-bbr.conf` строки `net.core.default_qdisc = fq` и
`net.ipv4.tcp_congestion_control = bbr`. Там же `net.core.rmem_max` и `net.core.wmem_max`
поднимаются до 4 МиБ: слушатель KCP — один UDP-сокет на всех хостов, и без этого Linux урезает
его буферы примерно до 208 КиБ, а при всплесках датаграммы теряются.

## Безопасность

- Авторизация — challenge-response на HMAC-SHA256. Секрет не передаётся по сети, одноразовые
  nonce не дают повторить перехваченный вход. Проверка взаимная: мод убеждается, что говорит с
  relay, который знает секрет, и не работает с подставным сервером.
- Внешний порт выбирает только relay, а локальный адрес — только мод хоста: соединения друзей
  всегда идут в его мир на `127.0.0.1`, и relay не может направить их куда-то ещё.
- Relay банит IP за перебор секретов по TCP и TLS, ограничивает число одновременных рукопожатий,
  туннелей и игроков с одного адреса. Неудачи по KCP не банят: адрес отправителя UDP можно
  подделать, и иначе кто угодно заблокировал бы чужой IP. Подбирать секрет бессмысленно и так:
  в нём 256 случайных бит.
- Файрвол после установки пропускает снаружи только порты relay и SSH.
- Relay работает от системного пользователя без прав, с фильтром системных вызовов и урезанным
  `/proc`; единственная его привилегия — порты ниже 1024 (для TLS на 443). Конфиг с секретами
  читают только root и сам relay (права 0640).
- Трафик игры relay не расшифровывает и не меняет. TLS дополнительно шифрует канал между хостом и
  VPS и маскирует туннель под HTTPS.
- Порты для игроков открыты всему интернету, как у любого сервера Minecraft. Мир защищают
  средства самой игры: проверка лицензий (online-mode) и белый список.

## Решение проблем

| Что видно | Причина |
|---|---|
| Установщик: «Не удалось скачать relay» | Сервер не открывает github.com. Поставьте relay с Windows через `deploy.ps1` |
| Установщик: «Порты уже заняты другой программой» | На сервере уже что-то слушает эти порты. Запустите установщик снова и ответьте «н» на вопрос о портах |
| В моде «relay недоступен» | Relay не запущен (`systemctl status mctunnel-relay`) или порт 25500 (443 для TLS) закрыт у хостера или в фаерволе |
| В моде по KCP «relay не ответил вовремя» | Закрыт UDP-порт 25500 у хостера или в фаерволе. Сеть может резать UDP целиком: тогда оставьте TCP |
| Порты открыты в панели хостера, а снаружи не отвечают | Некоторые облака применяют изменения файрвола только после перезагрузки виртуальной машины |
| В моде «неверный пользователь или секрет» | Пользователь или секрет не совпадают с `relay.json`: покажите данные ещё раз через меню установщика |
| В моде «слишком много неудачных попыток» | IP забанен на 15 минут за неверный секрет. Исправьте секрет и подождите или перезапустите relay |
| Друзья не могут зайти, а туннель открыт | Диапазон портов для игроков закрыт у хостера или в фаерволе |
| Часть друзей с одного IP не может зайти | Сработал `max_players_per_ip` (по умолчанию 8). Поднимите его в `relay.json` и перезапустите relay |

Журнал relay: `sudo journalctl -u mctunnel-relay -f`. Подробнее — с `"log_level": "debug"` в
конфиге и `sudo systemctl restart mctunnel-relay`.
